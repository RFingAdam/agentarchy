# upstream/

Everything that decides which parts of the upstream project get vendored, how they are renamed, and
what the last run produced. `bin/oal-dev-sync-upstream` reads the inputs and writes the reports;
`bin/oal-dev-check`'s `vendor-drift` gate (`--check`) fails if the tree stops matching them.

**Vendored files are never hand-edited.** Change a data file here and re-run
`bin/oal-dev-sync-upstream --apply`, or capture the edit with `bin/oal-dev-upstream-patch`.

## Inputs (hand-maintained)

| File | What it does |
|---|---|
| `PIN` | the upstream commit, a 40-char sha. `bin/oal-dev-upstream-fetch` caches that tree under `~/.cache/agentarchy/upstream/<sha>/`. |
| `REPO` | the `owner/name` slug the tarball is fetched from. |
| `VENDOR-MANIFEST` | `include <glob>` / `exclude <glob>`, one per line. |
| `RENAME-PATHS.sed` | renames the selected **paths**. |
| `RENAME-MAP.sed` | rewrites the **contents** of text files. |
| `EXCLUDE-BIN.regex` | one ERE; a `bin/` script whose text matches it is not vendored. |
| `FORCE-INCLUDE-BIN` | upstream `bin/` basenames vendored even when `EXCLUDE-BIN.regex` matches. |
| `NEEDS-PORT.regex` | one ERE; a vendored text file matching it is reported as needing work. |
| `patches/*.patch` | local edits, applied to the renamed tree in name order. |
| `EXCLUDED-ASSETS.md` | hand-kept list of excluded non-script assets that vendored files still reference. |

### VENDOR-MANIFEST

Globs are matched against **upstream (pre-rename) paths**, relative to the upstream root: the
manifest is read before `RENAME-PATHS.sed` runs, so it spells the upstream name, not `oal`.

- **Later lines win.** A path matched by an `include` on line 8 and an `exclude` on line 30 is
  excluded; the reverse order would vendor it. Excludes therefore live below the includes.
- `*` stays inside one path segment; `**` crosses `/`. Only `[A-Za-z0-9._/*-]` is allowed in a glob
  (the glob-to-regex conversion escapes `.` and nothing else, so anything else is refused).
- Anything not matched by an `include` is simply ignored, which is most of the upstream tree.
- Symlinks are never vendored. If the manifest *includes* one the sync dies rather than silently
  dropping a file, so a symlink has to be excluded explicitly.
- A "never vendor X" rule only exists if it is an `exclude` here. Prose in `CLAUDE.md` is not
  checkable; the gates are all text-based and cannot see inside an image (see
  2026-08-23).

### RENAME-PATHS.sed

Path renames, applied as a single `sed -E` pass over the list of selected paths. It is one blanket
rule, `s#omarchy#oal#g`, not a set of delimiter-specific ones: in the pinned tree the upstream name
is never glued into a longer path token -- `find . | grep -oE '[A-Za-z0-9]*omarchy[A-Za-z0-9]*' |
sort -u` yields exactly one token -- so there is nothing a narrower rule would protect, and narrower
rules did in practice miss `omarchy.sh`, `10-omarchy.conf`, `omarchy_hooks.conf`, `omarchy.webp`
and `com.omarchy.ytdlp.json`. That last one is load-bearing: Chromium resolves a native-messaging
host by matching the manifest *filename* against its `"name"` field, which the content rules had
already rewritten. Re-run that audit on every PIN bump (step (c) below).

Two upstream paths renaming onto the same destination would silently drop one, so the sync refuses
that too.

### RENAME-MAP.sed

Content rewrites for text files, `sed -E`, **order-sensitive**: URLs first, then paths, then env
vars and command prefixes, then the snake_case namespace, then the bare word, then prose
capitalisations. The URL rules must precede the word rules or they would rewrite the host inside a
URL and leave a broken link; the subdomain rule sits after the two plain-host rules so
`omarchy.org` still maps to this repo while `pkgs.omarchy.org` moves to the reserved `.invalid`
TLD instead of forging a resolvable look-alike host someone could register.

Binary files skip this pass and are copied byte-for-byte.

### EXCLUDE-BIN.regex / FORCE-INCLUDE-BIN / NEEDS-PORT.regex

`EXCLUDE-BIN.regex` triages `bin/`: a script mentioning Hyprland, Quickshell, `uwsm` and friends is
compositor-bound and is dropped. `FORCE-INCLUDE-BIN` lists upstream basenames to keep anyway (a
script whose only compositor tie is one launch line); every forced script is reported in
`NEEDS-PORT.txt` whether or not it matches `NEEDS-PORT.regex`. Both regex files are validated
before use -- an empty or malformed pattern would otherwise make the batched `grep` fail open and
vendor everything.

### patches/

Numbered `NNNN-<name>.patch`, applied with `patch -p1 -F0`: **fuzz is disabled**. See
`patches/README.md`.

## Reports (generated by `--apply`, compared by `--check`)

Do not edit these; `--check` fails if they drift from what a rebuild produces.

| File | Path convention | Contents |
|---|---|---|
| `VENDORED-FILES.txt` | repo paths | every path the sync owns. This is the ownership list: a file here must never be hand-edited, and a file *not* here is native. |
| `EXCLUDED-BIN.txt` | **upstream** paths | `bin/` scripts dropped by `EXCLUDE-BIN.regex`. They are never vendored, so they never exist under a renamed name; naming them upstream-side is the only unambiguous way to refer to them. |
| `NEEDS-PORT.txt` | repo paths | vendored files that matched `NEEDS-PORT.regex`, plus every `FORCE-INCLUDE-BIN` script. |
| `DANGLING.txt` | repo paths | `<vendored file> -> <script name>` for each call to a script that was excluded. That call is dead on this tree. |

`DANGLING.txt` covers *scripts* only. An excluded image or QML asset that a vendored file still
names is recorded by hand in `EXCLUDED-ASSETS.md`, because nothing can detect it automatically.

## Bumping PIN

1. Put the new sha in `PIN`.
2. `bin/oal-dev-sync-upstream --apply`.
3. **(a) Eyeball every new or changed binary asset.** `git diff --stat` lists them; open each one.
   No gate can see inside an image, so this step is the only thing standing between upstream's
   wordmark and a file called `themes/<x>/backgrounds/oal.webp`. Anything branded gets an `exclude`
   in `VENDOR-MANIFEST` and a row in `EXCLUDED-ASSETS.md` -- not a deletion, which the next
   `--apply` would undo. Name-based excludes are not enough on their own: three wallpapers carried
   the wordmark or the logo mark without ever mentioning the upstream project in their filename.
   The whole pre-existing wallpaper set was reviewed by eye on 2026-08-23 and those three removed,
   so a future bump only has to eyeball assets this diff shows as **new or changed**.
4. **(b) Diff the four reports against the previous commit.**
   `git diff HEAD -- upstream/VENDORED-FILES.txt upstream/EXCLUDED-BIN.txt upstream/NEEDS-PORT.txt upstream/DANGLING.txt`.
   New `EXCLUDED-BIN` entries mean upstream grew a compositor dependency; new `DANGLING` entries
   mean a vendored file started calling something we do not ship.
5. **(c) Audit the renamed paths.** Both must hold:
   ```
   find . -path ./.git -prune -o -iname '*omarchy*' -print |
     grep -v '^./upstream\|^./test/fixtures\|^./.sync\|^./.superpowers'   # must be empty
   (cd ~/.cache/agentarchy/upstream/<sha> && find . -mindepth 1 |
     grep -oE '[A-Za-z0-9]*omarchy[A-Za-z0-9]*' | sort -u)                # must print only: omarchy
   ```
   The second one is what makes the blanket path rule safe. If it ever prints a longer token,
   `RENAME-PATHS.sed` needs a narrower rule before that path is vendored.
6. **(d) Confirm the patches applied.** They apply without fuzz or the sync dies, so reaching this
   step means they did. A patch that died has to be regenerated, not force-fitted.
7. **(e)** `bin/oal-dev-check` -- seven `PASS` lines.
8. Commit, with the old and new sha in the message.

### Spot checks on file encodings

SVG/UTF-16 spot check done 2026-08-23: one SVG in the vendored set
(`default/chromium/extensions/yt-dlp/download-video.svg`), sed-safe; no UTF-16 assets. Re-check on
a PIN bump if `file(1)` starts reporting a wide encoding -- `RENAME-MAP.sed` is a byte-oriented
`sed` pass and would corrupt a UTF-16 file rather than rename it.
